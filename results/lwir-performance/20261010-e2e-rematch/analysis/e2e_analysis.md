# E2E access-unit 매칭 정식 재측정

## 실험 범위

- 캠페인: `20261010-e2e-rematch`
- 조건: B0, B1 각 3회
- 입력: `seq_001`, 640×480, 30 FPS, 971프레임
- 통계: 초기 60프레임 제외 후 각 실행을 요약하고 실행 3개의 통계를 평균
- 시계: Raspberry Pi가 PC를 NTP 기준으로 사용
- 실험 직전 Raspberry Pi system offset: 약 +0.069 ms

| 조건 | E2E 평균 | E2E P95 | Encoding 평균 | Encoding P95 |

## 단계별 latency

각 값은 초기 60프레임을 제외한 실행별 평균/P95를 계산한 뒤 3회 결과를
평균한 것이다.

| 단계 | B0 평균 | B0 P95 | B1 평균 | B1 P95 |
|---|---:|---:|---:|---:|
| Capture processing | 13.162 ms | 20.926 ms | 10.064 ms | 10.108 ms |
| Preprocess queue wait | 0.784 ms | 4.070 ms | 0.024 ms | 0.028 ms |
| Preprocess processing | 0.455 ms | 0.523 ms | 0.449 ms | 0.451 ms |
| Streaming queue wait | 0.185 ms | 0.496 ms | 0.043 ms | 0.047 ms |
| Streaming submit | 0.956 ms | 4.326 ms | 0.183 ms | 0.194 ms |
| Encoding | 1633.391 ms | 1705.495 ms | 3.540 ms | 4.449 ms |
| End-to-end | 1708.258 ms | 1717.953 ms | 54.339 ms | 55.181 ms |

B0의 지연은 대부분 인코더 내부 프레임 보류에서 발생했다. B1에서는
인코딩 평균이 3.540 ms까지 감소했으며, 전체 E2E에서 남은 시간은 캡처,
전처리, 전송, 수신 및 디코딩 경로를 포함한다.
